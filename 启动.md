  🧪 推荐测试路径

  1. 登录 Dashboard → http://localhost:3002/app/login
  用 john@acme.inc / Password1! 登录超级管理员（什么都能干），或 michael_scott@paperlayer.test / Password1!. 登录账户管理员。
  2. 体验 Inbox → 进 Conversations → 看已有 20 条会话（含文本/图片附件/电商订单等不同类型）
  3. 切 Inbox → 左侧栏切到不同 Inbox 看 9 个 channel（Website、API、Email、WhatsApp 等）数据怎么分布
  4. 试发消息 → 任一会话里回复 → 听浏览器是否出声（new_message 音效）
  5. Help Center 公开页 → Settings → Help Center → 找 portal slug → 访问 http://localhost:3002/hc/<slug>（公开，不需要登录）
  6. Widget 测试 → http://localhost:3002/widget_tests
  直接在页面里点聊天图标，跟 Acme Inc 的 Web Widget Inbox 互动
  7. 看发出的邮件 → http://localhost:8025
  触发密码重置、邀请 agent 等动作后会进 MailHog
  8. Captain AI（需 Enterprise 配置） → 此 OSS 版本 Captain 框架基础就绪，但完整 AI 功能（Firecrawl 爬文档、配额闸门）需要 Enterprise overlay 激活。Settings → Captain 里能看到 Assistants / Documents / Responses 的 UI 骨架。
  9. 切到 Acme Org → 右上角 profile → 切换 account → 看到完全独立的数据（多租户隔离验证）
  10. 看实时事件 → 打开浏览器 DevTools Network → WS 过滤 → 应能看到 ActionCable WebSocket 连接

  🛠️  常用运维命令

  # 查看所有容器状态
  docker compose ps

  # 看某个服务日志（实时）
  docker compose logs -f rails
  docker compose logs -f sidekiq

  # 跑 Rails console
  docker compose exec rails bundle exec rails console

  # 跑 RSpec
  docker compose exec rails bundle exec rspec spec/path/to/file_spec.rb

  # 重新种子（清空 account 数据再 seed）
  docker compose exec rails bundle exec rails runner \
    "Account.find(1).update!(name: 'Acme Inc'); Seeders::AccountSeeder.new(account: Account.find(1)).perform!; puts 'OK'"

  # 停止所有服务
  docker compose down

  # 停止并删数据（重启干净环境）
  docker compose down -v

  ---
  ⚠️  注意事项

  - 主端口已避开冲突：rails 暴露在 3002（3000/3001 被其他项目占）；redis 暴露在 16379（6379 被 basjoo-redis 占）；vite在 3036（标准）。
  - 不重启容器的情况下编辑 Rails 代码会自动重载（开发模式）。
  - 修改前端代码 Vite 会自动 HMR（无需刷新页面）。
  - MailHog 自动接管 SMTP，所以发出的所有邮件都在 localhost:8025 看，不发到真实邮箱。
  - 生产用别忘了改 SECRET_KEY_BASE、POSTGRES_PASSWORD、REDIS_PASSWORD（现在是 chatwoot_dev）。
  - 数据写入持久化在 docker volume chatwoot_postgres 和 chatwoot_redis 里，stop 容器不丢；docker compose down -v 才会清。
